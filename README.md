# Alert Bot — Telegram-алерты по вашим ценовым уровням

Приватный бот для интрадей-трейдинга. Вы ставите свои ценовые отметки — бот
следит за ценой и предупреждает, когда она к ним подходит, добавляя короткую
сводку: что об этом пишут аналитики.

## Как это устроено

Три независимых контура с разной частотой:

| Контур | Период | Что делает | Модель |
|---|---|---|---|
| Цена | 30 сек | свечи с площадки, ATR, детектор | нет |
| Новости | 10 мин | RSS → дедуп → фильтр → разбор | gpt-5-mini |
| Алерт | по событию | сводка из готового контекста | gpt-5-mini |

Три принципа, на которых держится остальное:

**Уровни задаёт человек, а не бот.** Ничего не вычисляется за вас: приходит
сообщение ровно о той отметке, которую вы поставили сами.

**Вся математика — в коде, модель работает только с текстом.** ATR, расстояния
и триггеры считаются на Python и передаются модели как факты, менять которые
запрещено. Числа, названные моделью, дополнительно сверяются с исходным текстом:
на живых данных примерно каждое восьмое оказывалось выдуманным.

**Алерты дороже тишины.** Гистерезис, cooldown, один алерт на инструмент за тик,
дневной потолок и тихие часы — без них бота замьютят на второй день.

## Быстрый старт

```bash
cp .env.example .env        # TELEGRAM_BOT_TOKEN, ADMIN_TG_ID, OPENAI_API_KEY
python3.12 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m scripts.check_setup
.venv/bin/python -m alert_bot.main
```

В Telegram: `/start` → **Инструменты** → **Добавить уровень**.

Ключ модели необязателен: без него бот работает полностью, только без новостной
сводки в алертах.

## Доступ и роли

Бот приватный: войти можно только по одноразовому инвайт-коду. Роли две.

| | Обычный пользователь | Администратор |
|---|---|---|
| Свои уровни и настройки | да | да |
| Подписка на инструменты | да | да |
| **Завести инструмент** | да, до `MAX_INSTRUMENTS_PER_USER` | без лимита |
| Отключить инструмент из реестра | нет | да |
| Выдать и отозвать доступ | нет | да |
| Ленты новостей, расход на модель | нет | да |

Инструменты заводит любой, а отключает только администратор, и это не
непоследовательность. Реестр общий: одна строка на символ и площадку, один
опрос на всех подписчиков. Добавление ничего чужого не ломает — в худшем случае
занимает слот, и от этого есть личная квота. Отключение бьёт по всем, кто на
инструмент подписан, включая тех, кто поставил по нему уровни. Поэтому человеку
доступно ровно то, что касается его самого: подписаться и отписаться. Если
нужный инструмент уже в реестре, второй раз он не заводится — человека просто
подписывают на существующий.

Уровни у каждого свои: чужих он не видит, его не видит никто.

Инструмент, на который `ORPHAN_TTL_HOURS` (по умолчанию сутки) никто не
подписан и по которому ни у кого нет уровней, отключается сам. Без этого
открытый реестр зарастает тем, что завели попробовать и забыли: опрос площадки
идёт по-прежнему, а слот из общего потолка занят. Отключение мягкое — свечи,
уровни и история остаются, повторное добавление возвращает инструмент вместе с
ними, и тому, кто его заводил, приходит сообщение. Уровень считается наравне с
подпиской: человек мог отписаться от алертов, но отметки оставить.

Администраторов может быть несколько. Первый — владелец из `ADMIN_TG_ID`, роль с
него не снимается из бота. Остальные заводятся двумя способами:

```bash
ADMIN_TG_ID=111222333,222333444    # список: первый — владелец, остальные админы
ADMIN_TG_IDS=222333444             # то же самое отдельной переменной
/grant_admin 222333444             # из бота, перезапуск не нужен
/admins                            # кто сейчас администратор
/revoke_admin 222333444            # снять роль; доступ к боту остаётся
```

Список принимается в обеих переменных: имена различаются одной буквой, и
требовать помнить, в какой из них список, а в какой одно число, — ловушка.

Роль выдаётся только тому, у кого доступ уже есть: сначала обычный путь через
`/gen_invite` и `/redeem`, и лишь потом роль — иначе она уходит по номеру
наугад. Себя и владельца разжаловать нельзя, иначе двое администраторов могут
запереть себя снаружи.

## Источники котировок

Площадка задаётся третьим словом при добавлении инструмента.

| Площадка | Что даёт | Ключ | Задержка |
|---|---|---|---|
| `bybit` (по умолчанию) | крипта | не нужен | реальное время |
| `okx`, `binance` и прочие из ccxt | крипта | не нужен | реальное время |
| `yahoo` | валюты, металлы, нефть, индексы | не нужен | 0 / ~10 мин |
| `oanda` | форекс и сырьё от брокера | демо-счёт | реальное время |

Умолчание — Bybit, а не Binance, хотя последняя популярнее. Binance банит по
IP (`HTTP 418`), а на арендованном хостинге адрес общий с чужими сервисами, так
что бан прилетает и без вины бота. Расхождение котировок между биржами — 0.006%
в среднем и 0.04% в худшем случае, то есть меньше самого мелкого шага порога
(0.05%): на момент срабатывания алерта выбор биржи повлиять не может. Bybit
отдаёт до 720 часовых свечей за запрос против 300 у OKX, а циклу нужно 200.

Binance никуда не делась — задаётся явно: `/add_instrument BTC/USDT binance`.

```bash
/add_instrument BTC/USDT              # крипта
/add_instrument USD/CAD yahoo         # валюты — реальное время
/add_instrument BRENT yahoo           # сырьё — задержка ~10 мин
```

Про задержку бот предупреждает в превью до добавления: при пороге в доли ATR
десятиминутное отставание означает, что алерт придёт после движения.

**Осторожно с суррогатами на крипто-бирже.** `EUR/USDT` — это евро к
стейблкоину, `XAUT/USDT` — токен на золото. Измеренное расхождение с настоящим
рынком: по евро 0.04×ATR (терпимо), по золоту **4.96×ATR** (негодно). Для валют
и металлов берите `yahoo` или `oanda`.

## Команды

**Пользователь**

| Команда | Что делает |
|---|---|

| `/redeem КОД` | активировать инвайт |
| `/subscribe` | выбрать инструменты |
| `/addlevel SYMBOL ЦЕНА [заметка]` | поставить уровень (`78000`, `78k`, `78 000`) |

**Админ** — видны в подсказке по `/` только администратору:

`/users` · `/revoke` · `/usage`

## Уровни

Уровень принадлежит автору: алерт уходит только ему, чужие уровни не видны и
недоступны. Работа идёт через кнопки — идентификаторы человеку не показываются.

Алерт приходит при движении **к** уровню, а не от него. Повторно по тому же
уровню бот молчит, пока цена не уйдёт на 1×ATR и не истечёт cooldown. При смене
цены уровня состояние сбрасывается: cooldown относился к прежней отметке.

Удаление настоящее — уровень уходит вместе с журналом срабатываний.

## Калибровка порога

`atr_k` нельзя выбрать умозрительно — от него зависит, придёт три сообщения в
сутки или сорок:

```bash
.venv/bin/python -m scripts.replay --symbol BTC/USDT --days 24 --sweep
```

Гоняет тот же `detector.evaluate_level`, что работает в проде, по историческим
свечам. На BTC за 25 суток:

```
atr_k=0.15  →  5.1 алертов/сутки · устоял 45% · пробит 54%
atr_k=0.3   →  7.0 алертов/сутки · устоял 54% · пробит 44%
atr_k=0.5   →  8.6 алертов/сутки · устоял 55% · пробит 41%
```

Метрика «дошла до уровня» намеренно не основная: алерт срабатывает в долях ATR
от уровня, поэтому касание происходит почти всегда и метрика насыщается под 100%
на любых порогах. Различает уровни другое — устоял он или был пробит.

## Расход на модель

Замерено на живых данных: 52 статьи и 3 алерта в сутки — **около $0.13/мес**.
Извлечение растёт слабо от числа инструментов: статья разбирается один раз и
раздаётся во все релевантные контексты. `DAILY_LLM_BUDGET_USD` — жёсткий потолок;
при исчерпании алерты продолжают уходить без сводки. Факт смотреть в `/usage`,
там же прогноз на месяц по текущему темпу.

## Развёртывание на сервере

### Что понадобится

VPS с 1 ГБ памяти и Docker. База растёт примерно на 200 КБ в сутки при пяти
инструментах.

### Установка

```bash
git clone <репозиторий> /opt/alert-bot && cd /opt/alert-bot
cp .env.example .env && nano .env
docker compose run --rm bot python -m scripts.check_setup
docker compose up -d --build
docker compose logs -f
```

Предполётная проверка проходит по каждой внешней зависимости отдельно — конфиг,
БД, биржа, Telegram, ленты, модель — и печатает внятную причину вместо стектрейса
на старте. Она же ловит отладочные значения, оставшиеся с локальной работы
(например `PRICE_POLL_SECONDS=10` — на сервере нужно 30).

### Обновление

```bash
git pull && docker compose up -d --build
```

Данные лежат на хосте в `./data`, пересборка их не трогает. Остановка корректная:
бот перестаёт опрашивать площадки, дожидается отправки уже поставленных в очередь
сообщений и только потом завершается.

### Проверка живости

Контейнер «запущен» и бот работает — разные вещи: цикл цены может уткнуться в
зависший сокет, пока процесс формально жив. Цикл на каждом обороте ставит отметку
в `data/heartbeat`, healthcheck смотрит на её возраст:

```bash
docker compose ps        # STATUS: healthy / unhealthy
```

Проверяется оборот цикла, а не поступление данных: на выходных форекс закрыт,
цены стоят, и это нормальное состояние, а не поломка.

### Резервные копии

```bash
./scripts/backup.sh      # в ./backups, хранит 14 дней
```

Обычный `cp` для SQLite не годится: база в режиме WAL, часть свежих записей лежит
отдельно, и простая копия рискует оказаться неполной. Скрипт снимает согласованный
снимок штатной командой `.backup`.

Crontab, ежедневно в 04:00:

```
0 4 * * * cd /opt/alert-bot && ./scripts/backup.sh >> backups/backup.log 2>&1
```

Восстановление: распаковать `.gz` поверх `data/alert_bot.db` при остановленном боте.

### Railway

Пятнадцать минут, около $5/мес: [deploy/RAILWAY.md](deploy/RAILWAY.md).

Два шага там критичны, и ошибка в них проявляется не сразу: **регион EU West**
(Binance отдаёт 451 американским IP) и **том на /app/data** (без него база
стирается при каждом деплое). Конфиг сборки — [railway.toml](railway.toml).

### Без Docker

Готовый systemd-юнит: [`deploy/alert-bot.service`](deploy/alert-bot.service),
инструкция в шапке файла.

### Чего делать нельзя

**Два экземпляра на один токен.** Telegram не допускает два одновременных
`getUpdates`: второй отбирает обновления у первого, и алерты теряются через раз.
В compose поэтому жёстко одна реплика. Для тестовой копии заводите отдельного
бота у @BotFather.

**Класть `.env` в образ.** Он подключается через `env_file` и остаётся на хосте;
`.dockerignore` исключает его из сборки.

## Тесты

```bash
.venv/bin/python -m pytest -q      # 316 тестов
```

Покрыто то, где ошибка тихая: полный цикл анти-спама, разные пороги у разных
подписчиков, изоляция уровней между пользователями, одновременная активация
инвайта, тихие часы через полночь, переход на летнее время в календаре сессий,
дедупликация новостей, отбраковка выдуманных моделью чисел, совместимость
параметров с моделью.

## Ограничения

- **Гэп через уровень не даёт алерта.** Детектор ищет подход; если рынок открылся
  за вашей отметкой, подхода не было — уровень пробит молча. Актуально для
  форекса после выходных.
- **Yahoo — неофициальный источник.** Формат не гарантирован, библиотека может
  сломаться после изменений на их стороне. Для боевых денег правильнее брокерский
  API — провайдер OANDA написан и ждёт токена.
- **Сырьё на Yahoo отстаёт на ~10 минут.** Для входа по уровню поздно.
- **Динамически добавляемые источники новостей — только RSS.** Под каждый
  JSON-API нужен свой парсер.
- **Это не инвестиционная рекомендация.** Бот сообщает о техническом событии и
  пересказывает публикации третьих лиц.
