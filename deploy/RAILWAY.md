# Развёртывание на Railway

Пятнадцать минут. Два шага из шести — те, где ошибка не видна сразу, а
проявляется позже: регион и том. Они отмечены.

## 1. Создать сервис

New Project → **Deploy from GitHub repo** → выбрать репозиторий.

Railway увидит `Dockerfile` и `railway.toml`, соберёт сам. Первая сборка идёт
около четырёх минут.

## 2. ⚠️ Регион — EU West

Settings → **Region** → **EU West (Amsterdam)**.

**Binance блокирует американские IP** и отдаёт `HTTP 451 Unavailable For Legal
Reasons`. По умолчанию Railway разворачивает в US West, и все крипто-инструменты
молча перестанут получать данные — бот будет работать, но половина инструментов
окажется мёртвой.

Из четырёх регионов Railway подходят EU West и, вероятно, Southeast Asia.

## 3. ⚠️ Том для базы

Settings → **Volumes** → **New Volume** → mount path: `/app/data`

Без тома SQLite ложится внутрь контейнера и **стирается при каждом деплое** —
вместе с уровнями пользователей, историей срабатываний и накопленными новостями.
Обнаруживается это только после первого обновления, когда данные уже потеряны.

Одного гигабайта хватит надолго: база растёт примерно на 200 КБ в сутки.

## 4. Переменные окружения

Variables → **Raw Editor** → вставить целиком:

```
LLM_PROVIDER=openai
OPENAI_API_KEY=<из вашего .env>
TELEGRAM_BOT_TOKEN=<из вашего .env>
ADMIN_TG_ID=<ваш telegram id>

DB_PATH=/app/data/alert_bot.db
PRICE_POLL_SECONDS=30
NEWS_POLL_SECONDS=600

MAX_INSTRUMENTS=10
MAX_ALERTS_PER_USER_PER_DAY=25
DAILY_LLM_BUDGET_USD=0.25

DEFAULT_ATR_K=0.3
DEFAULT_MIN_SCORE=4.0
COOLDOWN_HOURS=4

EXTRACTION_MODEL=gpt-5-mini
BRIEF_MODEL=gpt-5-mini
```

Отличия от локального `.env`: `DB_PATH` указывает на том, `PRICE_POLL_SECONDS`
поднят с отладочных 10 до 30 — чаще опрашивать биржи смысла нет.

`PORT` Railway подставляет сам, задавать не надо: по нему поднимается эндпоинт
проверки живости.

## 5. Проверка

После деплоя в логах должно появиться:

```
БД готова: /app/data/alert_bot.db
HTTP-проверка живости слушает порт ...
Бот @... запущен
Цикл цены запущен, интервал 30 c
```

Признаки, что шаг пропущен:

| Симптом | Причина |
|---|---|
| `тик не удался: ... 451` по крипте | регион не EU West |
| данные пропали после деплоя | том не подключён |
| сервис перезапускается по кругу | смотрите `/health` в логах |

## 6. Перенос существующей базы

Если хотите сохранить уже заведённые уровни:

```bash
railway login
railway link
railway run --service <имя> -- python -c "pass"   # проверить связь
```

Проще: заново пройти `/add_instrument` и расставить уровни через `/mylevels`.
Их немного, а возня с копированием SQLite в том займёт больше времени.

## Обновление

`git push` — Railway пересобирает и деплоит сам. Том не трогается.

## Что важно не сделать

**Не масштабировать в две реплики.** Telegram не допускает два одновременных
`getUpdates`: второй экземпляр отбирает обновления у первого, и алерты начинают
теряться через раз. Railway позволяет поднять реплики одной кнопкой — не надо.

**Не включать sleep на неактивности.** Бот должен работать круглосуточно: он
опрашивает цену, а не отвечает на запросы.

## Сколько будет стоить

Railway считает по потреблению: $20 за vCPU и $10 за ГБ памяти в месяц.
Замерено на этом боте: 256 МБ и около 8% CPU.

```
0.25 ГБ × $10   = $2.50
0.08 vCPU × $20 = $1.60
том 1 ГБ        = $0.15
                  ──────
                   ~$4.25/мес
```

Тариф Hobby стоит $5 и включает $5 кредита на потребление, так что фактически
выйдет около пяти долларов. Расход растёт линейно с числом инструментов —
следите в разделе Usage.

Отдельно модель: около **$0.13/мес** при нынешнем потоке новостей, смотреть
в боте через `/usage`.
